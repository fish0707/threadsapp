# Threads `keyword_search` App Review 送審清單

> 目的：讓 App 通過 Meta 審核，從「只搜得到自己貼文」解鎖成「可搜公開熱門貼文」。
> 對象權限：`threads_keyword_search`（`threads_basic` 通常隨基本流程即可，`threads_content_publish` 另外送審）。

---

## 0. 送審前先確認（缺一項就會被退）

- [ ] App 已可正常運作（OAuth 登入、搜尋、生成、發佈都能跑）。
- [ ] **隱私政策網址**（公開可連、內容對得上你 App 的資料行為）。
- [ ] **資料刪除說明 / 回呼**（我們已做 `/api/auth/threads/deletion`）。
- [ ] App 圖示（1024×1024）、顯示名稱、用途分類填好。
- [ ] 有一個**可被 Meta 審核員實際操作或觀看**的環境（正式網址或螢幕錄影）。
- [ ] 商業驗證（Business Verification）— 若被要求，需準備公司／個人證明文件。自用測試階段不一定觸發，但搜公開貼文常會要求。

---

## 1. 隱私政策（最常見卡關點）

需要一頁公開網頁，至少說明：
- 你會透過 Threads API 取得哪些資料（公開貼文內容、作者公開資訊、你授權帳號的 user id / token）。
- 用途（產生貼文草稿、發佈貼文）。
- 儲存方式與期間（token 加密儲存於資料庫；草稿儲存於資料庫）。
- 使用者如何要求刪除資料（提供聯絡方式或刪除流程）。
- 第三方服務揭露（Vercel、Supabase、Google Gemini／Anthropic）。

> 可放在 `https://你的網域/privacy`。要的話我可以幫你產一頁隱私政策範本頁面。

---

## 2. 權限用途說明（Permission rationale）

審核表單會要你針對 `threads_keyword_search` 說明「為什麼需要、怎麼用」。範本（可直接改）：

```
我們的應用程式「脈脈 Threads 經營助手」協助使用者經營自己的 Threads 帳號。
使用者輸入一個主題關鍵字後，我們呼叫 keyword_search（search_type=TOP）取得
該主題當天的公開熱門貼文，作為「靈感參考」呈現給使用者瀏覽。

使用 threads_keyword_search 的唯一目的，是讓使用者了解某主題目前的熱門內容趨勢，
並據以撰寫自己的原創貼文。我們不會抓取、轉售或重新發佈他人貼文內容，
僅作為使用者本人創作時的參考顯示。資料不會用於廣告或建立使用者輪廓。
```

要點：
- 明確說「**作為參考顯示**」，不是抓資料轉售／重新發佈。
- 對應到畫面上的「靈感動態」功能。
- 不要寫成「自動大量爬取」或「監控他人」——會被退。

---

## 3. 操作流程（Step-by-step / 螢幕錄影腳本）

審核員需要能重現功能。準備一段 1～2 分鐘錄影，照這個腳本：

1. 開啟 App 首頁，點「連結 Threads 帳號」，完成 OAuth 授權（顯示授權畫面 → 回到 App 顯示已連結）。
2. 在搜尋框輸入主題（例：`職場`），按「搜尋熱門」。
3. 畫面出現「靈感動態」公開熱門貼文卡片（**這一步就是在展示 keyword_search**）。
4. 勾選 1～2 篇參考 → 選風格 → 按「生成草稿」→ 出現 AI 生成的原創草稿。
5. （可選）按「發佈到 Threads」展示發佈流程。

> 錄影需清楚拍到「輸入關鍵字 → 出現搜尋結果」的因果，審核員才看得出你真的用到這個權限。

---

## 4. 測試帳號 / 測試說明

- 提供審核員可用的**測試 Threads 帳號**（或說明用他們自己的帳號授權即可）。
- 在「App Review 說明欄」附上：正式網址、測試步驟、預期結果、上面那段錄影連結。

---

## 5. 送審操作位置

Meta 開發者後台 → 你的 App →
1. **使用案例（Use cases）→ 存取 Threads API → 權限和功能**：把 `threads_keyword_search` 旁的狀態從「測試中」推進到「要求進階存取（Request Advanced Access）」。
2. 依表單填寫：用途說明（第 2 節）、操作步驟（第 3 節）、上傳／貼上錄影。
3. **App 從開發模式切換為上線（Live）** 才會正式生效（基本資訊、隱私政策、圖示需齊全才能切上線）。
4. 送出後等待審核（通常數個工作天，可能來回補件）。

---

## 6. 常見被退原因 & 對策

| 被退原因 | 對策 |
|----------|------|
| 隱私政策無法連、或內容與功能不符 | 用第 1 節清單補齊，網址需公開可連 |
| 錄影看不出用到該權限 | 照第 3 節腳本，明確拍「輸入關鍵字→出現結果」 |
| 用途寫得像爬蟲／轉售他人內容 | 強調「使用者本人創作時的參考顯示」 |
| App 還在開發模式 | 切換為 Live（補齊基本資訊） |
| 缺資料刪除機制 | 已內建 `/api/auth/threads/deletion`，於後台填入 |
| 未完成商業／身分驗證 | 依 Meta 要求上傳文件 |

---

## 7. 審核通過後

- 不需改任何程式：本專案的 `searchTopic()` 已直接呼叫 `keyword_search`，
  通過後同一支 API 就會回傳**公開**熱門貼文（而非只有自己的）。
- 注意額度：每使用者滾動 24 小時最多 2,200 次查詢（跨 app 共用）。
  本專案已用「同主題當天快取」節流，正常使用不易觸頂。

---

### 還沒過審期間的替代方案
若想在審核通過前就有「公開熱門文」可參考，可評估第三方資料源
（Apify / EnsembleData 等），抽象化在 `src/lib/threads.ts` 的資料來源層即可替換，
但有成本與合規考量（見計畫書風險表）。
